# EA_Monitor v3.8 仕様書

- ファイル: `EA_Monitor_v3.8.mq4`(置き場所: `MQL4/Experts`)
- 版の表記: 次の3か所で統一している。
  - ファイル名
  - `#property version "3.80"`
  - 起動ログ「EA_Monitor v3.8 起動」と、Telegramの起動通知「[EA_Monitor v3.8] 起動しました」
- 旧版はそのまま残す。
  - `EA_Monitor.mq4`(v2)
  - `EA_Monitor_v3.5.mq4`(v3.0。v3.5の名前で稼働中だった版)
  - `EA_Monitor_v3.6.mq4`
  - `EA_Monitor_v3.7.mq4`
- 作成日: 2026-09-25
- v3.7 までの機能を全て含む。変えていない部分は v3.7・v3.6 の仕様書を参照。
- 注意: この環境ではMQL4のコンパイルを確認できない。MetaEditorでコンパイルし、エラーが出たら内容を知らせてほしい。

## 0. v3.8の変更点(v3.7からの差分)

### 0-1. 口座の種類(リアル/デモ)の切り替え

| 設定 | 既定値 | 内容 |
|---|---|---|
| 口座の種類(AccountMode) | リアル口座 | リアル口座 / デモ口座 を選ぶ |
| DemoFilePrefix | `demo_` | デモ口座の時、全ファイル名の頭に付ける文字 |
| TelegramInDemo | false | デモ口座でも Telegram 通知するか |

- **リアル口座**: ファイル名は今までと同じ(`ea_monitor.csv` など)。本番の記録がそのまま続く。
- **デモ口座**: 全ファイル名の頭に `demo_` が自動で付く(例: `demo_ea_monitor_events_v38.csv`)。同じ Drive フォルダに同期しても本番のファイルとぶつからない。
- デモ口座では、月末月初の停止(自動売買ボタンの操作)は使わない。Telegram は TelegramInDemo=true の時だけ送り、文頭に「[デモ 口座番号]」を付ける。
- **選んだ種類とログイン中の口座が違う時は起動しない**(アラートを出して止まる)。デモを選んだままリアルで動かして月末月初の停止が効かなくなる、リアルを選んだままデモで動かして本番のファイルに書き込む、を防ぐため。
- 画面の稼働表示は、デモ口座では「デモ口座:記録のみ」になる。

### 0-2. イベント記録にオシレーターを追加(`ea_monitor_events_v38.csv`)

- 列が増えたため新しいファイル名にした(v3.7 の `ea_monitor_events_v37.csv` はそのまま残る)。
- v3.7 の全列の後ろに、M1・M5・M15 それぞれについて次の6列を追加(計18列)。
  - `rsi0` / `rsi1`: RSI(14)。0 = 形成中の足、1 = 確定足
  - `stoK0` / `stoD0`: ストキャス(9,3,3)の %K・%D(形成中の足)
  - `stoK1` / `stoD1`: 同じ(確定足)
- 列名の例: `m5_rsi0;m5_rsi1;m5_stoK0;m5_stoD0;m5_stoK1;m5_stoD1`
- 目的: ナンピンフィルター(公式説明「オシレーターで過熱を検知」)の数値を決める。毎分記録(m1state)は確定足の値だけなので、形成中の足で判定している場合に決められなかった(解析25・26)。

### 0-3. ナンピン待機中の記録(`ea_monitor_nanpin_wait_v38.csv`)

| 設定 | 既定値 | 内容 |
|---|---|---|
| EnableWaitLog | true | 出力するか(EnableEventLog=true の時だけ動く) |
| WaitFileName | `ea_monitor_nanpin_wait_v38.csv` | ファイル名 |
| WaitLogSeconds | 10 | 記録の間隔(秒) |

- ラグナロクの束で、時間と値幅の条件(NanpinMinSeconds=420 / NanpinMinPts=110)が揃ってから次のナンピンが入るまでの間だけ、10秒ごとに1行を書く。ナンピンが入ると止まり、次に条件が揃うとまた始まる。
- 列: `time;account;logic;side;basket;legs;last_leg_price;last_leg_time;sec_since_last_leg;cond_met_time;sec_since_cond;bid;ask;adv_now_pts;adv_max_pts;bounce_pts;cond_now` + 0-2 と同じオシレーター18列。
  - `cond_now`: その瞬間も条件を満たしているか(1/0)。条件が揃った後に値幅が戻って外れた時は 0。
- 待機の最後の行と NANPIN の行を並べると、「入らなかった時」と「入った時」のオシレーターを比べられる。
- 量の目安: 1つの束が50分待つと約300行。

### 0-4. 起動時の口座履歴の書き出し(`ea_monitor_history_v38.csv`)

| 設定 | 既定値 | 内容 |
|---|---|---|
| EnableHistoryDump | true | 起動時に書き出すか |
| HistoryFileName | `ea_monitor_history_v38.csv` | ファイル名 |

- 起動時に1回、ラグナロクのマジック(848/929)の決済済みの全取引と、今の建玉を書き出す。**ファイルは毎回上書き**(履歴の写しのため)。
- 列: `account;status;ticket;symbol;type;lots;open_time;open_price;close_time;close_price;sl;tp;profit;swap;commission;magic;comment`(status は closed / open)。
- **MT4 の「口座履歴」タブで「全期間」を表示してから起動すること**。表示している期間の分しか取れない。
- 目的: 公開デモ口座の過去の全取引(a〜e)で、発火条件・ナンピン・利確の標本を増やす。

### 0-5. 画面表示の既定値(Shinさんの設定に合わせた)

| 設定 | v3.7 | v3.8 |
|---|---|---|
| 表示位置 | 左上 | **右上** |
| 表示位置: 縦 | 20 | **30** |
| 足替わりタイマーの文字サイズ | 14 | **30** |

- その他の表示の設定は v3.7 と同じ。

### 0-6. その他

- 設定するチャートの説明を「GOLDmicroのチャート」から「Ragnarokが取引する銘柄のチャート」に変更(デモ口座の銘柄名が違う場合があるため)。
- Telegram のトークンはコードに書いていない(入力欄に入れる)。

## 1. 使い方

### 1-1. リアル口座(本番)

1. `EA_Monitor_v3.8.mq4` を本番の MT4 の `MQL4/Experts` に置き、MetaEditorでコンパイルする。
2. v3.7 をチャートから外し、v3.8 を同じ GOLDmicro のチャートに設定する。
   - 口座の種類: **リアル口座**(既定のまま)。
   - Telegram のトークンは入力欄に入れる。
   - 「DLLの使用を許可する」は v3 と同じ(月末月初の停止を使うため)。
3. ファイル名は今までと同じ。イベント記録だけ `ea_monitor_events_v38.csv` に変わる。

### 1-2. 公開デモ口座

1. **本番の MT4 ではログインしない**(本番口座から切り替わり、本番の Ragnarok が止まる)。XM の MT4 を別のフォルダにもう1つ入れ、そちらでデモ口座にログインする。
2. `EA_Monitor_v3.8.mq4` を、そちらの MT4 の `MQL4/Experts` に置いてコンパイルする。
3. 「口座履歴」タブで右クリック →「全期間」を選ぶ。
4. Ragnarok が取引している銘柄(取引タブで確認。GOLD か GOLDmicro)のチャートに v3.8 を設定する。
   - 口座の種類: **デモ口座**。
   - Telegram は既定で送らない(TelegramInDemo=false)。
5. 出力先はデモ側の MT4 の `MQL4/Files`。Drive に同期する場合、ファイル名は `demo_` で始まるので本番とぶつからない。

## 2. 確認のしかた

- 起動ログに「EA_Monitor v3.8 起動: 口座=番号(デモ または リアル), ファイル名の例=…」と出る。
- 口座の種類を間違えると「口座の種類の設定(…)と、ログイン中の口座(…)が違います」のアラートが出て止まる。
- 起動ログに「口座履歴を書き出しました(N件)」と出る。N が 0 の時は、口座履歴の表示期間かマジック番号(848/929)を確認する。
- `ea_monitor_events_v38.csv` の行末に18個の数字(RSI・ストキャス)が付いている。
- 条件が揃ってナンピンを待っている間、`ea_monitor_nanpin_wait_v38.csv` が10秒ごとに増える。
