## 0. v3.9の変更点(v3.8からの差分)

### 0-1. 足の頭のティック記録(`ea_monitor_bartick_v39.csv`)

目的: b の初弾が「条件のそろった足の約3割」でしか入らない理由を調べる(解析32)。約定は足の頭0〜5秒のどこかで起きており、1分足では見えないため、足の頭のティックを全て記録する。

| 設定 | 既定値 | 内容 |
|---|---|---|
| EnableBarTickLog | true | 足の頭のティックを記録するか |
| BarTickFileName | `ea_monitor_bartick_v39.csv` | ファイル名(デモ口座では頭に `demo_` が付く) |
| BarTickSeconds | 10 | M1 足の始まりから何秒の間を記録するか |

- 記録するのは、このEAを設定したチャートの銘柄(Ragnarok が取引する銘柄のチャートに設定すること。v3.7 から同じ)。
- 1ティック=1行。1分の分をメモリにためて、記録の時間が過ぎたらまとめて書き込む(1ティックごとにファイルを開かない)。
- 新しいファイルなので、既存のCSVの列は変わらない。

列(区切りは `;`):

| 列 | 内容 |
|---|---|
| bar_time | M1 足の始まり(サーバー時間) |
| tick_time | ティックの時刻(サーバー時間、秒まで) |
| sec_in_bar | 足の始まりからの秒数 |
| ms_from_first | その足の最初のティックからのミリ秒(PCの時計。同じ秒の中の順番を見るため) |
| tick_no | その足で何番目のティックか |
| bid / ask / spread_pts | 価格とスプレッド(pts) |
| bar_open / bar_high / bar_low | その瞬間の形成中の M1 足の始値・高値・安値 |
| close1 / close3 | 1本前・3本前の M1 足の終値 |
| mom3_pts | bid − 3本前の終値(pts)。b の方向の判定 |
| k433 / d433 | M1 ストキャス(4,3,3)・Low/High・形成中の足の %K・%D(解析31の条件) |
| k433_cc / d433_cc | 同じ(Close/Close) |
| k422_cc_c1 / d422_cc_c1 | M1 ストキャス(4,2,2)・Close/Close・確定足(解析32で最良) |
| k933 / d933 | M1 ストキャス(9,3,3)・形成中の足(以前の候補) |
| m5_rsi9 | M5 RSI(9)・形成中の足(ナンピンフィルター、解析29) |
| open_b_buy / open_b_sell | その瞬間に b の買い・売りの束が開いているか(1/0) |

- 容量の目安: GOLD で1分あたり10〜60行、1行約200バイト → 1日 3〜15MB。調べ終わったら EnableBarTickLog=false にする。
- b の初弾の時刻は `ea_monitor_events_v38.csv` の ENTRY 行と突き合わせる(bar_time と約定時刻で結合)。

### 0-2. 解析での使い方

1. 条件のそろった足(解析31)で、入った足と入らなかった足の、0〜10秒のティックの動きを比べる。
2. 約定の直前のティックで、どの値(K・D・mom3 など)がしきい値をまたいだかを調べる。
3. 本番とデモの両方で動かせば、同じ足で片方だけ入った4本(解析32)の違いも見られる。

## 1. 設置

- v3.8 と同じ。本番(リアル口座)とデモ(公開デモ口座、別の MT4)の両方で、v3.8 を外して v3.9 を設定する。
- 口座の種類の設定(リアル/デモ)を必ず合わせること(違う時は起動しない)。
