# a/b/c バックテスト v2(検証済みルール版) — 第7回

スクリプト: `tools/ragnarok/backtest_ragnarok_abc_v2.py`
データ: M1足 2026-09-03 15:03 〜 09-23 07:17(19.7日、18,681本)、`ea_monitor.csv`(09-22 10:36〜09-23 07:17)
口座の初期値: 180,901円(09-23朝の残高113,596円＋クレジット67,305円)

## 0. 結論

- 検証済みのルールを全て反映した。実ログの初弾をそのまま使った再現検証では、**バスケットの88%でレグ数が一致**する。
- ただし、**ナンピンの待機フィルター(未特定)が無いため、ナンピンが実機より多くなる**。09-23未明の買いバスケットでは、実機が10レグで止まったのに、モデルは18レグまで進んだ。
- その結果、上限40レグのままだと、**実機が耐えた09-23未明に、モデルだけがロスカットする**。破綻の判定は、このフィルターを特定するまで参考値。
- レグ数の上限を実測の最大(12)に抑えると、実ログの期間は証拠金維持率が最低139%で耐える。19.7日間では、3回中1回(seed 0)が09-09にロスカットした。
- 収支の結果は、ナンピン待機フィルターと初弾の発火条件という2つの未特定部分で大きく変わる。**現時点で「このEAは何日で破綻する/いくら稼ぐ」とは言えない。**

## 1. 実装したルール

| 項目 | 内容 | 根拠 |
|---|---|---|
| 初弾の方向 | bid − k分前のM1足の終値(b: k=3、c: k=11、a: k=20) | 第3〜6回。63/68、41/46、23/23 |
| 判定する足 | b/c: M1足の始値、a: M5足の始値 | 第4回 |
| 同じ方向の再エントリー間隔 | b 6分、c 9分、a 7.5分 | 第4回 |
| ナンピン | 直前レグから420秒以上 かつ bidで100pts以上の逆行 | 第2回 |
| ロット | 0.10×1.5^n、11レグ目以降は×1.2。丸める前の値に掛ける | 0.10〜5.54まで実測と一致 |
| 利確 | 加重平均建値から 1レグ+70pts / 2レグ以上+140pts。足の高値・安値で判定し、利確水準で約定 | 第2〜3回 |
| スプレッド | 54pts(買いはask、売りはbidで約定) | spread_pts の中央値(51〜57) |
| 口座 | 1lot=657円の証拠金、1ドル×1lot=157.4円、維持率20%でロスカット(足の終値で判定)。余剰証拠金が足りない発注は見送る | 第3回5節 |

未実装(未特定):
- 初弾の発火条件。`--fire always`(条件を満たせば必ず入る)と、`--fire prob`(実測の発火率 b 15%/c 7%/a 13% でランダム)の2通りで代用。
- ナンピンの待機フィルター。
- 大ロットのバスケットが+140ptsより手前で決済される条件。

## 2. 再現検証(`--replay`: 実ログの初弾139件の時刻・方向・約定価格をそのまま使用)

| 項目 | 結果 |
|---|---|
| レグ数が一致 | 122/139(88%) |
| モデルのほうが多い | 11件(うち大きい差: 09-23 03:03〜03:19開始の買い a/b/c で 実機10/10/8 → モデル18/18/16) |
| モデルのほうが少ない | 6件(09-22 14:38〜14:45開始の b/c売りで 8→4、10→8 など。実機はモデルが利確した水準を越えても決済していない) |
| モデルの利確が、実ログの次の初弾より前 | 127/131 |

口座を付けた場合(180,901円):

| 上限レグ数 | 最大含み損 | 最大合計ロット | 最低維持率 | 結果 |
|---|---|---|---|---|
| 40(実機の設定) | −179,812円 | 131.05 | 16% | 09-23 05:37 にロスカット(**実機は耐えた**) |
| 12(実測の最大) | −134,456円 | 74.35 | 139% | 耐える |

→ 実機は、待機フィルターでナンピンを止めて持ちこたえている。**待機フィルターの特定が、リスク評価の最優先課題**。
