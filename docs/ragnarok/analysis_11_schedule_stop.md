## 3. 結論

1. **提案のスケジュールでは、口座を守る効果は確認できなかった**。耐えた数は停止なし4 → 指標+提案1。
2. ロスカットの日時は、どのパターンでもほぼ同じ4日(07-21火、07-23木、08-05水、08-11火)に集中。**月曜朝・金曜深夜・月末月初ではなく、火〜木のトレンド日**で起きている。止めた時間帯は、そもそも危険の中心ではない。
3. 口座の上限を外すと、最大含み損は−200万〜−440万円で、口座(約18万円)の10倍以上。スケジュールで止めても、この水準はほとんど下がらない(上限12レグで−444万→−309万円)。利確は1〜4割減る。
4. このモデルは、ナンピンの待機フィルター(未特定)が無いため実機よりナンピンが多い。実機のリスクはこれより小さい可能性がある。ただし「スケジュールで止めれば安全になる」という根拠は得られなかった。

## 4. 示唆

- リスクを下げるには、「いつ止めるか」より「**逆行が続いたら止める**」仕組みが要る。候補:
  - 日足の始値(日本時間7時)から一定幅(40〜60ドル)動いたら、逆方向の新規を止める。
  - 1つのバスケットのレグ数・合計ロット・含み損が一定を超えたら、Telegramで警告する(EA_Monitorで実装可能)。
- 提案のスケジュールは、利確機会が減るだけで大きな害も無い。運用上の安心(週明け・週末・月末月初の急変を避ける)として採用するのは自由だが、**安全策の本体にはならない**。
